1. Endpoint

Método: POST

URL (ambiente de teste):

https://erp-teste.calibrescientific.com.br:8170/rest/CLBAPI10/incluicliente

Content-Type: application/json

Use a autenticação REST padrão do Protheus do ambiente (usuário/senha ou token conforme configuração do AppServer).

2. Comportamento geral

Inclusão

Se o a1_cgc não existir na SA1 → operação 3 (inclusão).

_message:
“Cliente incluido com sucesso no Protheus”

Alteração (upsert)

Se o a1_cgc já existir → operação 4 (alteração).

_message:
“Cliente alterado com sucesso, pois ja existia registro cadastrado no Protheus”

Prioridade dos dados: o que vier no JSON sempre prevalece. A API só completa campos auxiliares quando não vierem (ex.: nome reduzido, país, espelho de cobrança).

Chaves: use lowercase no JSON (a1_nome). O fonte converte para maiúsculo internamente.

3. Regras e validações

3.1 Campos obrigatórios no JSON (sem default)

Se faltar qualquer um abaixo (ou vier vazio), a API não grava e retorna Error 431 listando os campos:

a1_tpfret, a1_conta, a1_naturez, a1_crvbol, a1_contrib, a1_vend, a1_tabela, a1_cond, a1_sativ1, a1_xfatpar, a1_xmultpv, a1_xdtfun

3.2 Município × UF (CC2)

Se informar a1_cod_mun + a1_est, a API valida na tabela CC2 (igual ao gatilho da tela CRMA980).
Se a combinação for inválida → Error 431 (ex.: município de SP com UF RS).
Se válida → preenche/atualiza a1_mun com o nome oficial da CC2.

3.3 Inscrição estadual × contribuinte

  • PJ sem a1_inscr → assume ISENTO.
  • Se a1_contrib = "2" (não contribuinte) → força a1_inscr = "ISENTO" antes da validação de UF.
  • UF do cadastro e código do município devem ser coerentes, senão a validação fiscal de IE falha.

3.4 Pessoa (F/J)

Se a1_pessoa não vier: CPF (até 11 dígitos) → F; CNPJ (14) → J.

3.5 Endereço de cobrança

Se a1_endcob, a1_munc, a1_estc, a1_cepc (e bairro cob) vierem no JSON, são usados.
Se não vierem, a API espelha o endereço principal. Nunca sobrescreve valor já enviado no JSON.

3.6 SoftObrig — A1_CONDPAG

A1_CONDPAG é campo do módulo SIGAEEC. Na CRMA980 fica em branco e não aparece na tela.
No ExecAuto o dicionário (X3_OBRIGAT) ainda exigiria o campo. A API desliga essa obrigatoriedade somente durante a gravação e restaura em seguida. Não envie a1_condpag. O campo oficial de condição de pagamento nesta integração é a1_cond.

3.7 O que a API NÃO faz

  • Não altera A1_MSBLQL (bloqueio). Se o cliente nascer inativo (1), é regra do Protheus/SX3/crédito — não da API.
  • Não exige todos os campos X3_OBRIGAT do dicionário SA1 — só o conjunto de negócio mapeado abaixo.

Erros comuns

SituaçãoMensagem típica
JSON inválido Error 423 — estrutura do JSON
Faltou campo obrigatório da API Error 431 - Campos obrigatorios nao informados no JSON: a1_tpfret, ...
Município ≠ UF Error 431 - a1_cod_mun [...] incompativel com a1_est [...] (CC2).
Falha no ExecAuto / MVC Error 425 - Falha na execução da inclusão: ... (detalhe do campo no log)
IE × UF inválidos Mensagem de inscrição estadual inválida para a UF — revise a1_est, a1_cod_mun, a1_inscr, a1_contrib

7. O que não enviar

  • a1_condpag — exclusivo SIGAEEC; use a1_cond.
  • a1_filial — controlado pelo ambiente (xFilial).
  • Não é necessário enviar todos os campos X3_OBRIGAT do dicionário SA1.

8. Checklist rápido

  1. JSON com Content-Type application/json.
  2. CNPJ/CPF só números em a1_cgc.
  3. a1_est + a1_cod_mun coerentes na CC2.
  4. Os 12 campos obrigatórios da API preenchidos (incluindo a1_xdtfun).
  5. Se não contribuinte: a1_contrib=2 e IE ISENTO.
  6. Para inclusão “limpa”, use CNPJ novo (CNPJ repetido = alteração).
  7. Recompile o CLBApi10_cliente.prw após mudanças no fonte.
